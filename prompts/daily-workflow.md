# 📅 毎日の記事作成ワークフロー

> **概要**: 毎日1回「今日の記事お願い」と言うだけで、トレンド調査→記事候補提案→執筆→レビュー→push まで全自動で実行される。
>
> **あなたの作業**: 候補から1つ選ぶだけ（所要時間: 30秒）

---

## 運営者ペルソナ（テーマ選定の判断基準）

| 項目 | 内容 |
|------|------|
| 年齢 | 33歳 |
| 職業 | IT系エンジニア・フルリモート |
| 家族構成 | 子供2人（5歳 + 0歳） |
| 住環境 | 持ち家一戸建て（積水ハウス） |
| 趣味 | ガジェット好き |
| ターゲット読者 | 自分と同じ30代・子育て世代・IT/ガジェット好き |

### ペルソナに基づくテーマ選定ルール

1. **「5歳児 + 0歳児のパパ」目線を最優先する**
   - 5歳児視点: 知育タブレット、子供が触って大丈夫か、騒音で昇寝かけないか
   - 0歳児視点: 安全性・誤飲防止、夜泣き中の静音性、育児で手が離せない時の時短家電
   - 例: ロボット掃除機 → 床のおもちゃを巻き込まないか？赤ちゃんの昨寝中に回せる静かさ？

2. **フルリモート×ガジェット好きの視点を活かす**
   - 毎日在宅だからこそわかる長期使用感、家の中のネットワーク環境、スマートホーム化
   - デスク環境のこだわり（モニター、キーボード、デスク周り）は強み
   - スペック比較を表で整理、アプリの使い勝手や連携機能も評価する
   - 例: デスクチェア → 8時間座りっぱなしのリアル評価、Wi-Fiルーター → 一戸建て全部屋に届くか

3. **一戸建て（積水ハウス）ならではのテーマも狙える**
   - 床面積が広い前提の家電（ロボット掃除機のマッピング、全館空調、Wi-Fiメッシュ）
   - 庭付き一軒家: アウトドアリビング、防犯カメラ、外構メンテナンス
   - 例: 空気清浄機 → LDK20畴でも効く？、スマートロック → 積水ハウスとの相性

3. **ジャンルの優先順位（ペルソナ適合度順）**

   | 優先度 | ジャンル | 理由 |
   |:------:|---------|------|
   | ★★★ | ガジェット・テック系 | ガジェット好き×ITエンジニア。最も説得力がある |
   | ★★★ | フルリモート・デスク環境 | 毎日在宅だからこそのリアルレビューが可能 |
   | ★★★ | 子育て×家電（5歳+0歳） | 乳幼児がいる家庭の安全性・時短ニーズに共感大 |
   | ★★★ | 一戸建て・スマートホーム | 積水ハウス一軒家の実体験。広い家前提の家電レビュー |
   | ★★☆ | 時短家電・生活効率化 | 0歳育児中は時間がない。食洗機/乾燥機等 |
   | ★★☆ | 健康管理・運動不足対策 | フルリモートで運動不足になりがち |
   | ★☆☆ | 季節家電（加湿器/扇風機等） | 汎用テーマ。一戸建ての広さ前提で書ける |
   | ★☆☆ | アウトドア・庭活用 | 庭付きならではの記事も可能 |

4. **NGテーマ（ペルソナと乖離するもの）**
   - 高級ブランド品、美容コスメ（女性特化）、学生向け格安品
   - 超ニッチな専門機器（読者層が狭すぎる）
   - マンション専用テーマ（賃貸前提の原状回復DIY等）

5. **記事の語り口**
   - 一人称は特に固定しない（「自分」「筆者」等を自然に使い分け）
   - 「5歳の上の子が触りたがるんですよね」「0歳の下の子が寝ている横で使ってみた」等の具体的エピソード
   - 「フルリモートで8時間座りっぱなしのリアルな感想」「LDKで使ってみて」等の生活感
   - ガジェット好きならではの深掘り（スペック表・アプリの使用感・他デバイスとの連携）

## 使い方

### Step 1: 指示を出す

Copilot Chat に以下のいずれかを送る:

```
今日の記事お願い
```

```
記事作ってほしい
```

これだけでOK。

---

### Step 2: 候補を選ぶ

Copilot が以下の形式で候補を提示する:

```
📊 本日のトレンド調査結果（2026年2月22日）

| # | テーマ | おすすめ度 | 種別 | スタイル | 理由 |
|---|--------|:---------:|:----:|:--------:|------|
| 1 | 加湿器 おすすめ      | ★★★★★ | レビュー | A | 乾燥ピーク期。検索急上昇中 |
| 2 | 花粉症の時期と原因    | ★★★★☆ | 知識   | F | 既存レビュー記事への誘導に最適 |
| 3 | モバイルバッテリー 比較 | ★★★☆☆ | レビュー | C | 春の外出シーズン。通年ニーズ |

💡 おすすめ: 候補1「加湿器」— 季節ドンピシャ＆アフィリ収益が見込める
```

あなたは番号を1つ返すだけ:
```
1
```

---

### Step 3: 全自動実行（見てるだけ）

Copilot が以下を自動で実行:

1. **スクリプト実行** — `post.ps1` or `knowledge.ps1` で記事の雛形を生成
2. **記事執筆** — スタイル別プロンプトで本文を完成
3. **セルフレビュー** — Step 2 プロンプトで改善点を抽出→反映
4. **チェックリスト** — `review-checklist.md` の観点で最終確認
5. **公開設定** — `draft: false` に変更
6. **git push** — 自動デプロイ

完了後に以下が表示される:
```
✅ 記事を公開しました！
📝 タイトル: 【2026年版】加湿器おすすめランキング｜人気3選を徹底比較
🔗 URL: https://mononikki.com/posts/humidifier-2026/
📁 ファイル: content/posts/2026-02-22-加湿器/index.md
```

## Copilot 側の内部処理フロー

> 以下は Copilot が裏で実行する手順。ユーザーは意識しなくてよい。

### Phase 1: トレンド調査

1. **季節・時期の考慮**
   - 現在の月から季節イベント・需要を特定
   - 2月→花粉/乾燥/バレンタイン後、3月→引越し/新生活、6月→梅雨、等

2. **ウェブでトレンド調査**
   - Google Trends（日本）で急上昇キーワードを確認
   - 楽天市場の人気ランキングを確認
   - 季節商品・話題のニュースを確認

3. **既存記事との重複チェック**
   - `content/posts/` を確認し、同じテーマの記事がないか確認
   - 既存記事と関連するテーマは「知識記事（Style F）」で内部リンク強化

4. **候補の評価基準**

   | 基準 | 重み | 説明 |
   |------|:----:|------|
   | ペルソナ適合度 | ★★★ | 30代子育てIT系パパが書いて自然か？読者が共感する？ |
   | 季節マッチ度 | ★★★ | 今この時期に検索される？ |
   | 紹介コード活用 | ★★★ | `data/referrals.yaml` の enabled な紹介リンクを貼れるテーマか？ |
   | 収益ポテンシャル | ★★☆ | アフィリ商品単価が高い？ |
   | 競合の少なさ | ★★☆ | ロングテールで狙えるか？ |
   | 既存記事との相乗効果 | ★★☆ | 内部リンクで相互に強化できる？ |
   | サイトのバランス | ★☆☆ | レビューと知識記事の比率は適切？ |

   > **紹介コード優先ルール**: `data/referrals.yaml` で `enabled: true` の紹介リンクがある場合、
   > そのカテゴリに関連するテーマは候補表に必ず1つ以上含め、おすすめ度に ★+1 のボーナスを付ける。
   > 記事本文中には `{{</*/* referral "id" */*/>}}` ショートコードで紹介カードを自然に挿入する。

### Phase 2: 記事生成

1. **レビュー記事（Style A-E）の場合**
   ```powershell
   .\scripts\post.ps1 "キーワード" -Style X
   ```
   - 楽天APIで商品情報を自動取得
   - 雛形 Markdown を生成
   - カバー画像を自動生成

2. **知識記事（Style F）の場合**
   ```powershell
   .\scripts\knowledge.ps1 "テーマ" -Slug "english-slug" -RelatedPost "related-slug"
   ```
   - 楽天API不要
   - 関連レビュー記事への内部リンクを自動設定

### Phase 3: 執筆

1. 対応するスタイルプロンプト（`prompts/style-X-*.md` の Step 1）を使って本文を執筆
2. front matter の `title` と `description` をSEOルールに従って設定
3. `slug` を英語で設定
4. **紹介コード挿入**: `data/referrals.yaml` の `enabled: true` なリンクのうち、記事テーマに関連するものがあれば `{{</*/* referral "id" */*/>}}` を本文の適切な位置に挿入する
   - 挿入位置の目安: 記事後半のまとめ付近、または関連するセクション内
   - 無関係なテーマに無理に挿入しない

### Phase 4: レビュー & 改善

1. 同スタイルプロンプトの Step 2 を使ってセルフレビュー
2. 指摘された改善点を反映
3. `review-checklist.md` の全項目を確認

### Phase 5: 公開 & デプロイ

1. `draft: true` → `draft: false` に変更
2. Hugo ビルドで問題ないか確認
3. `git add` → `git commit` → `git push`

## 記事タイプのバランス目安

| 週のペース | レビュー記事 (A-E) | 知識記事 (F) |
|:---:|:---:|:---:|
| 週3記事 | 2本 | 1本 |
| 週5記事 | 3〜4本 | 1〜2本 |
| 毎日 | 5本 | 2本 |

> 知識記事は「信頼性UP + AdSense収益 + レビュー記事への内部リンク」が目的。
> アフィリ記事だけのサイトにならないようバランスを取る。

## 注意事項

- **1日1記事**が基本。量より質を優先
- 同じスタイルが3連続しないようにする
- 知識記事は**必ず既存レビュー記事への内部リンク**を入れる
- Hugo ビルドが通ることを確認してから push する
