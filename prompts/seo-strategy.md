## 2. キーワード戦略

### 2-1. キーワード選定の基本方針

**ターゲット**: 購入検討段階の検索ユーザー（BOFU = Bottom of Funnel）

```
検索意図の優先度:
  1位: 「商品カテゴリ + おすすめ」 — 購入意志が高い（例: 空気清浄機 おすすめ）
  2位: 「商品カテゴリ + 比較」    — 比較検討中（例: ロボット掃除機 比較）
  3位: 「商品カテゴリ + ランキング」— 信頼できる序列を求めている
  4位: 「悩み + 対策」            — 課題解決型（例: 花粉症 対策 グッズ）
  5位: 「商品名 + レビュー」      — 特定商品の評価を知りたい
```

### 2-2. キーワード構造（3層モデル）

```
メインKW（タイトルに必ず入れる）
  └─ サブKW（H2見出しに含める）
       └─ ロングテールKW（本文に自然に散りばめる）

例: 空気清浄機の記事
  メインKW: 「空気清浄機 おすすめ」
  サブKW:   「空気清浄機 一人暮らし」「空気清浄機 花粉」「空気清浄機 安い」
  ロングテール: 「空気清浄機 1万円以下 コスパ」「シャープ プラズマクラスター 口コミ」
```

### 2-3. キーワード選定プロセス

記事を作成する前に、以下のステップでキーワード調査を行う。

1. **メインKW候補を決める** — 楽天APIの検索キーワードをベースに
2. **Google検索でサジェストを確認** — 検索窓に入力し、候補を5〜10個収集
3. **上位10記事を確認** — どんな切り口で書いているか把握（差別化ポイントを探す）
4. **競合の弱いロングテールを狙う** — 「年度 + カテゴリ + おすすめ」は定番
5. **キーワードマッピングシートに記録**（下記テンプレート参照）

### 2-4. キーワードマッピング — 既存記事

| 記事 | メインKW | サブKW | slug |
|---|---|---|---|
| 空気清浄機 | 空気清浄機 おすすめ | 一人暮らし, 花粉, 安い | `air-purifier-2026` |
| ロボット掃除機 | ロボット掃除機 おすすめ | 安い, 一人暮らし, 水拭き | `robot-vacuum-2026` |
| ワイヤレスイヤホン | ワイヤレスイヤホン おすすめ | コスパ, 通話, 耳を塞がない | `wireless-earbuds-2026` |
| デスクチェア | デスクチェア おすすめ | 腰痛, 安い, テレワーク | `desk-chair-2026` |
| 花粉症対策グッズ | 花粉症 対策 グッズ | 室内, マスク以外, おすすめ | `hay-fever-goods-2026` |

## 3. タイトル設計ルール

### 3-1. タイトルテンプレート

```
パターン A: 【{年度}年版】{メインKW}ランキング｜人気{N}選を徹底比較
パターン B: {悩み}に効く！{メインKW}のおすすめ{N}選【{年度}年】
パターン C: {商品A} vs {商品B}｜{メインKW}を{観点}で比較してみた
パターン D: {シーン}に最適な{メインKW}は？おすすめ{N}選を紹介
パターン E: {商品名}を{期間}使った正直レビュー｜{メインKW}選びの参考に
```

### 3-2. タイトルのSEOルール

- **32文字以内**を目標（Google検索結果で切れない長さ）
- メインKWは**タイトルの前半**に配置する
- 年度を入れる（「2026年」→ 鮮度アピール）
- 数字を含める（3選、5選、○○円以下 など）
- 同じタイトルパターンを連続させない（AI臭を避ける）

## 4. メタディスクリプション設計

### 4-1. テンプレート

```
{悩み/目的}にぴったりの{メインKW}を厳選！{訴求ポイント}。{記事のユニークな価値}をご紹介します。
```

### 4-2. ルール

- **120文字以内**（Google表示上限は約120文字 / モバイル70文字）
- メインKWを**最初の30文字以内**に含める
- フロントマターの `description` に設定
- 「徹底解説」「完全ガイド」等の陳腐な表現を避ける

## 5. 見出し構造のSEOルール

### 5-1. H1 → H2 → H3 の階層

```
H1: 記事タイトル（自動出力、1つだけ）
  H2: 大セクション（メインKW or サブKWを含む）
    H3: 小セクション（ロングテールKW or 具体的な話題）
      H4: 補足（必要な場合のみ、SEO効果は薄い）
```

### 5-2. 見出しの書き方ルール

- H2にはメインKWまたはサブKWを**必ず1つ**含める
- H2の数は **5〜8個**（少なすぎると薄い、多すぎると散漫）
- 見出しの形式を**混ぜる**（疑問形・断言・名詞止め・「〜してみた」等）
- H2だけ読んでも記事の流れが分かるようにする

**悪い例（AI臭が強い）:**
```
## 空気清浄機の選び方
## おすすめの空気清浄機3選
## 空気清浄機のメリット
## 空気清浄機のデメリット
## まとめ
```

**良い例（自然で検索意図に応える）:**
```
## そもそも空気清浄機って本当に必要？
## 失敗しない空気清浄機の選び方3つのポイント
## 【1万円以下】コスパ最強の空気清浄機はこれ
## シャープ KC-35T7を実際に使ってみた感想
## 花粉シーズンに間に合う？いま買うならこの1台
```

## 6. 内部リンク戦略

### 6-1. 基本方針

記事数が少ない初期段階でも、**将来の内部リンク設計**を意識して書く。

```
カテゴリ構造（計画）:
  レビュー/
    ├── 家電（空気清浄機, ロボット掃除機）
    ├── ガジェット（ワイヤレスイヤホン）
    ├── 家具（デスクチェア）
    └── 健康・生活（花粉症対策グッズ）

  比較/
    └── 〇〇 vs △△ 系の記事

  お役立ち/                       ← ✅ Style F（knowledge.ps1）で作成
    ├── 知識・基礎解説（「〜とは？」「〜の仕組み」）
    ├── ハウツー・メンテナンス（「〜の掃除方法」「〜のやり方」）
    └── 季節・トレンド情報（「〜の時期まとめ」「2026年春の〜」）
```

### 6-2. 内部リンクルール

- 各記事の末尾「まとめ」セクションに**関連記事リンクを2〜3本**設置
- 本文中で他カテゴリの商品に言及する場合は**自然にリンク**
- 目安: 1記事あたり**2〜5本**の内部リンク（記事が増えてから追加してOK）
- アンカーテキストにキーワードを含める（「こちら」「詳細はここ」は NG）

### 6-3. カテゴリ / タグの使い分け

| 項目 | 用途 | 例 |
|---|---|---|
| **カテゴリ** | 記事の大分類（1記事1カテゴリが理想） | レビュー, 比較, お役立ち |
| **タグ** | 横断的な属性（1記事3〜6個） | 商品名, 価格帯, 用途, シーズン |

**現状の問題**: 全記事が `categories: ["レビュー"]` のみ → カテゴリの意味がない
**改善案**: カテゴリを「家電レビュー」「ガジェットレビュー」「生活用品レビュー」等に細分化

## 7. コンテンツ品質ガイドライン（E-E-A-T）

Google が重視する **E-E-A-T**（経験・専門性・権威性・信頼性）を意識する。

### 7-1. Experience（経験）

- 「使ってみた」「試した」等の一人称体験を含める
- 使用期間・使用環境など具体的な情報を書く
- 良い点だけでなく**不満点も正直に**書く

### 7-2. Expertise（専門性）

- スペックの数値を正確に記載（メーカー公式サイトから引用）
- 専門用語には簡単な説明を添える
- 比較基準を明確にする（「なんとなくおすすめ」は NG）

### 7-3. Authoritativeness（権威性）

- 「運営者情報」ページを充実させる（`content/page/about/`）
- 記事数・カテゴリの網羅性を高める（特定ジャンル10記事以上が目標）
- 外部からの被リンク獲得は長期目標

### 7-4. Trustworthiness（信頼性）

- アフィリエイトリンクには `rel="nofollow noopener"` を付ける（✅ 実装済み）
- 価格は「執筆時点の価格」と明記するか、頻繁に更新する
- 免責事項・プライバシーポリシーを設置する
- HTTPS 通信（✅ GitHub Pages は自動HTTPS）

## 9. 画像SEO戦略

### 9-1. 現状の問題

- 楽天API画像が **128x128px** — Google画像検索に載らないサイズ
- 記事の `image`（アイキャッチ）が全記事 **空欄** — OGP/SNSシェア時に画像なし
- `alt` 属性が商品名のコピー — SEO的に弱い

### 9-2. 改善方針

| 画像種別 | サイズ目安 | 用途 |
|---|---|---|
| **アイキャッチ** | 1200×630px | OGP、SNSシェア、ホーム一覧 |
| **商品画像** | 400×400px以上 | 楽天カード内表示 |
| **比較表画像** | 800×450px | 記事内の視覚的比較 |

### 9-3. アイキャッチ画像の作成方法

1. **Canva** (無料) で作成 → `static/images/posts/` に配置
2. ファイル名: `{slug}.webp` (例: `air-purifier-2026.webp`)
3. フロントマターで指定: `image: "images/posts/air-purifier-2026.webp"`
4. WebP形式で200KB以下を目標（PageSpeed対策）

### 9-4. 楽天API画像の高解像度化

現在のAPI呼び出しで `?_ex=128x128` → `?_ex=400x400` に変更する。
`scripts/post.ps1` の画像取得部分を修正。
