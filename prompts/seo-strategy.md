### 1-3. JSON-LD 構造化データ設計

記事タイプごとに以下のスキーマを出力する:

```
全記事共通:
  - Article スキーマ（author, datePublished, dateModified, headline, image）
  - BreadcrumbList スキーマ（ホーム > カテゴリ > 記事名）

ランキング・比較記事 (Style A/C):
  - ItemList スキーマ（ランキング順位をリッチリザルトに）

個別レビュー記事 (Style E):
  - Product + Review スキーマ（商品名, 評価, レビュー本文）

お役立ち記事 (Style F):
  - FAQPage スキーマ（記事内のQ&Aセクションから自動生成）
```

実装場所: `layouts/partials/structured-data.html` を新規作成し、`single.html` から呼び出す。

### 1-4. リダイレクト方針

- GitHub Pages の場合は `layouts/aliases.html` で `<meta http-equiv="refresh">` を利用
- 旧URLは最低6ヶ月間リダイレクトを維持する

**ペルソナ修飾語（差別化用）:**
- 「フルリモート」「在宅勤務」「リモートワーク」
- 「子供がいる家庭」「子育て世帯」「パパ」「乳幼児」

- 「30代」「共働き」「時短」
- 「ガジェット」「IT系」「エンジニア」

**ペルソナ修飾語の使用ルール:**
- タイトルに修飾語を入れるのは **3記事に1回** 程度（入れすぎると検索ボリュームが激減する）
- 入れる場合は **サブKWやH2見出し** に配置するのが基本
- メインKWの月間検索ボリュームが500未満の場合は修飾語を入れない（さらに絞ると需要ゼロになる）
- 本文中には自然に散りばめてOK（「うちは在宅勤務なので…」等の文脈）

### 2-1. キーワード選定の基本方針

**ファネル別の記事割合目標:**

```
                          ┌─────────────────────┐
  TOFU（認知）30%         │ Style F: お役立ち    │ ← PVを稼ぐ集客記事
  「〇〇とは」「〇〇 仕組み」│ 「〇〇の掃除方法」   │   収益記事への内部リンクで誘導
                          ├─────────────────────┤
  MOFU（検討）30%         │ Style B/D: 悩み解決  │ ← 課題を認識→商品を知る
  「〇〇 対策」「〇〇 選び方」│ Style C: 比較      │   比較表で購買意欲を高める
                          ├─────────────────────┤
  BOFU（購入）40%         │ Style A: ランキング  │ ← 収益の主力
  「〇〇 おすすめ」「〇〇 レビュー」│ Style E: 体験レポ │   楽天/Amazonリンクで成約
                          └─────────────────────┘
```

**検索意図の分類と対応スタイル:**

| 2 | 「カテゴリ + 比較」 | MOFU→BOFU | Style C (比較) | ◎ 高 |
| 3 | 「カテゴリ + ランキング」 | BOFU | Style A (ランキング) | ◎ 高 |

| 5 | 「悩み + 対策」 | MOFU | Style B (悩み解決) | ○ 中 |

### 2-2. キーワード選定の数値基準

**狙うキーワードの条件:**

| 条件 | 基準値 | 理由 |
|------|--------|------|
| **月間検索ボリューム** | 100〜3,000 | 100未満は需要不足、3,000超は大手・企業サイトが独占 |
| **キーワード難易度 (KD)** | KD30以下 | 新規ドメインでも3〜6ヶ月で上位表示可能な範囲 |
| **単語数** | 2〜4語 | 1語は競合激化、5語以上は需要不足 |
| **検索結果に個人ブログがあるか** | 上位10件中2件以上 | 個人ブログが皆無ならそのKWは避ける |
| **検索結果の文字数** | 上位記事が5,000字以下 | 自サイトの記事で質・量ともに上回れる見込み |

**Go / No-Go 判断フロー:**

```
① 検索ボリューム 100〜3,000 か？
   → No → 却下（需要なし or 勝てない）
   → Yes → ②へ

② Google検索上位10件に個人ブログが2件以上あるか？
   → No → 却下（企業ドメインに勝てない）
   → Yes → ③へ

③ 上位記事の内容に「ペルソナ特化の切り口」がないか？
   → ない → 差別化チャンス → GO（ペルソナ修飾語で差別化）
   → ある → ④へ

④ 上位記事の品質・網羅性を上回れるか？
   → Yes → GO（より詳しい/最新の記事を書く）
   → No → 却下 or ロングテールに変更
```

### 2-3. キーワード調査ツールキット

AIが直接使えないツールも含め、調査フローで参照するツールを定義する。

| 用途 | ツール | 使い方 | AIが使えるか |
|------|--------|--------|-------------|
| **サジェスト一括取得** | ラッコキーワード | メインKWを入力→関連語を一括取得 | ✕（人間がCSVを渡せばAI分析可能） |
| **検索ボリューム** | Ubersuggest / aramakijake.jp | KW入力→月間ボリューム確認 | ✕（結果をAIに渡して判断可能） |
| **競合分析** | Google検索（手動） | 上位10記事のタイトル・見出しを確認 | ✕（コピペすればAI分析可能） |
| **共起語分析** | 共起語検索ツール | メインKWの共起語を取得→本文に自然に含める | ✕（結果をAIに渡せば配置可能） |
| **順位チェック** | Google Search Console | 掲載順位・CTR・表示回数を確認 | ✕（CSVをAIに渡せば分析可能） |
| **KW候補の大量生成** | AI (ChatGPT/Copilot) | 「〇〇に関するロングテールKWを30個出して」 | ◎ |
| **検索意図の分類** | AI | 「このKWは情報収集/比較検討/購入のどれか」 | ◎ |
| **見出し構成への組込** | AI | KWリストから記事アウトライン生成 | ◎ |

**AIへのキーワード調査依頼テンプレート:**

```

ラッコキーワードのサジェスト結果:
  （ここにCSVを貼り付け）

Google検索上位5記事のタイトル:
  1. ○○○
  2. ○○○
  ...

指示:
- サブKWを5〜8個選定し、H2見出しへの配置を提案
- ロングテールKWを10個提案し、本文での自然な使い方を例示
- 競合との差別化ポイントを3つ提案
- ペルソナ修飾語を入れるべきか判断
```

### 2-5. キーワード選定プロセス（詳細版）

記事を作成する前に、以下のステップでキーワード調査を行う。

```
Step 1: KW候補出し（10分）
  ├─ 楽天APIの検索キーワードからメインKW候補を決める
  ├─ ラッコキーワードでサジェスト一括取得（CSVダウンロード）
  └─ AIに「〇〇に関するロングテールKWを30個」を依頼

Step 2: 数値チェック（10分）
  ├─ aramakijake.jp or Ubersuggest で月間検索ボリューム確認
  ├─ Go/No-Go判断フロー（2-2）を適用
  └─ ボリューム100〜3,000の範囲に入るKWを選別

Step 3: 競合調査（15分）
  ├─ Google検索でメインKWを検索、上位10記事のタイトル・URL・見出しを記録
  ├─ 個人ブログが2件以上あるか確認
  ├─ 上位記事にない切り口（ペルソナ特化）を探す
  └─ 上位記事の文字数を概算（差別化できるか判断）

Step 4: KW確定 & マッピング（5分）
  ├─ メインKW / サブKW / ロングテール / 共起語 を確定
  ├─ 下記マッピングシートに記録
  └─ 記事スタイル（A〜F）を決定

Step 5: カニバリチェック（3分）
  └─ 既存記事のマッピングと照合し、KW重複がないか確認（2-7参照）
```

### 2-7. キーワードカニバリゼーション防止

**原則: 1メインKW = 1記事**

同じメインKWで複数記事を書くと、自サイト内で順位を奪い合う。

**カニバリ判定基準:**
- メインKWが完全一致 → 🔴 統合すべき（1記事にまとめる）
- メインKWの主要語が一致（例: 「空気清浄機 おすすめ」と「空気清浄機 ランキング」）→ 🟡 要注意（検索結果が同じ記事群なら統合）
- サブKWレベルの重複 → 🟢 問題なし（内部リンクで相互参照）

**カニバリが発生した場合の対処:**
1. 片方の記事に統合してリダイレクト
2. canonical タグで正規記事を指定
3. 片方の切り口を大幅に変更（例: ペルソナ特化に振り直す）

**新記事作成前のチェック:**
- 上記マッピング（2-6）と照合して、メインKWが既存記事と被らないか確認
- 被る場合は「リライトで対応」or「切り口変更」を選択

## 3. トピッククラスター戦略

### 3-1. 基本概念

**「このサイトは○○について詳しい」とGoogleに認識させる**ための戦略。
1つのテーマについて「柱記事（ピラーページ）＋ 複数のクラスター記事」を作り、内部リンクで結合する。

### 3-3. クラスター運用ルール

- 1クラスターにつき **ピラー1記事 + クラスター3〜7記事** を目標
- 各クラスター記事からピラー記事へ **必ず内部リンク**
- ピラー記事内にクラスター記事を **まとめリンクとして設置**
- まず1クラスターを完成させてから次のクラスターに着手（中途半端に複数クラスターを広げない）
- **現状の優先クラスター**: ワイヤレスイヤホン（既存記事が最も多い）

## 4. コンテンツファネル設計（集客→収益の導線）

### 4-1. 記事の役割定義

| 役割 | 目的 | 記事スタイル | KPI | 収益手段 |
|------|------|-------------|-----|---------|
| **集客記事** | PVを稼ぎ、サイトへの入口を増やす | Style F | PV数、検索表示回数 | AdSense（自動広告） |
| **検討記事** | 悩みを深掘りし、商品への関心を高める | Style B/D | 滞在時間、収益記事へのクリック率 | AdSense + 一部アフィリエイト |
| **収益記事** | 商品を比較・推薦し、購入に繋げる | Style A/C/E | アフィリエイトクリック率、成約率 | 楽天/Amazonアフィリエイト |

### 4-2. 導線設計の基本パターン

```
パターン1: 知識→ランキング
  「空気清浄機 フィルター 仕組み」(F) → 「空気清浄機 おすすめ」(A)
  導線: 記事末尾「選ぶなら…おすすめランキングもチェック」+ 内部リンク

パターン2: 悩み→解決→商品
  「花粉症 室内 対策」(B) → 「空気清浄機 おすすめ」(A)
  導線: 対策の1つとして空気清浄機を紹介し、ランキング記事へリンク

パターン3: レビュー→比較→ランキング
  「Sony LinkBuds レビュー」(E) → 「ワイヤレスイヤホン おすすめ」(A)
  導線: 「他のイヤホンとも比べたい方はこちら」+ 内部リンク

パターン4: シーン→商品
  「テレワーク イヤホン おすすめ」(D) → 個別レビュー記事 (E)
  導線: シーン記事で紹介した商品の詳細レビューへリンク
```

### 4-3. 導線の実装ルール

- 集客記事（Style F）には **末尾に必ず1〜2本の収益記事リンク** を設置
- 収益記事（Style A/C）には **冒頭に「この記事で分かること」** を入れ、離脱を防ぐ
- 各記事の **本文中に最低1箇所**、自然な文脈で関連記事へリンク
- アンカーテキストは必ずKWを含む（「こちら」「詳細はここ」は NG）

### 5-2. タイトルのSEOルール

- **32文字以内**を目標（Google検索結果で切れない長さ）

- 数字を含める（3選、5選、○○円以下 など）

- 「徹底解説」「完全ガイド」「必見」等の陳腐パワーワードは使わない

## 7. 見出し構造のSEOルール

### 7-1. H1 → H2 → H3 の階層

```
H1: 記事タイトル（自動出力、1つだけ）
  H2: 大セクション（メインKW or サブKWを含む — 5〜8個）
    H3: 小セクション（ロングテールKW or 具体的な商品名）
      H4: 補足（必要な場合のみ、SEO効果は薄い）
```

### 7-2. 見出しの書き方ルール

- H2にはメインKWまたはサブKWを**必ず1つ**含める
- H2の数は **5〜8個**（少なすぎると薄い、多すぎると散漫）
- 見出しの形式を**混ぜる**（疑問形・断言・名詞止め・「〜してみた」等）
- H2だけ読んでも記事の流れが分かるようにする
- **共起語をH3に意識的に含める**（Googleの関連性シグナル強化）

**悪い例（AI臭が強い）:**
```
## 空気清浄機の選び方
## おすすめの空気清浄機3選
## 空気清浄機のメリット
## 空気清浄機のデメリット
## まとめ
```

**良い例（自然で検索意図に応える）:**
```
## そもそも空気清浄機って本当に必要？
## 失敗しない空気清浄機の選び方3つのポイント
## 【1万円以下】コスパ最強の空気清浄機はこれ
## シャープ KC-35T7を実際に使ってみた感想
## 花粉シーズンに間に合う？いま買うならこの1台
```

### 7-3. 強調スニペット対策の見出し設計

Googleがスニペットとして抽出しやすい構造:

- **「○○とは？」の見出し** → 直後に **1〜2文で端的に定義** → その後に詳細
- **「○○の方法」の見出し** → 直後に **番号付きリスト** で手順
- **「○○のメリット/デメリット」** → **箇条書きリスト** で列挙
- **比較系の見出し** → 直後に **テーブル** で比較

```markdown
例:
## タンク式食洗機とは？

タンク式食洗機とは、水道工事なしで使える卓上型の食器洗い乾燥機のこと。
給水タンクに手動で水を入れて使うため、賃貸でも設置できるのが最大の特徴だ。

以下、タンク式食洗機の主な特徴を整理する:

- 工事不要で賃貸OK
- 給水は手動（1回あたり約5L）
- ...
```

## 8. 内部リンク戦略

### 8-1. 基本方針

**トピッククラスター（セクション3）の内部リンクで「サイトの専門性」を構築する。**

```
カテゴリ構造:
  まとめ/                         ← ランキング・おすすめ系（Style A）
    ├── 家電（空気清浄機, ロボット掃除機, 食洗機）
    ├── ガジェット（ワイヤレスイヤホン, スマホ）
    └── 生活（時短家電, 節約）

  レビュー/                       ← 個別商品レビュー（Style E）、悩み解決（Style B）
    ├── 家電レビュー
    ├── ガジェットレビュー
    └── サービスレビュー（楽天モバイル等）

  解説/                           ← お役立ち・知識記事（Style F）
    ├── 知識・基礎解説（「〜とは？」「〜の仕組み」）
    ├── ハウツー・メンテナンス（「〜の掃除方法」「〜のやり方」）
    └── 季節・トレンド情報（「〜の時期まとめ」「2026年春の〜」）
```

### 8-2. 内部リンクルール

**配置ルール:**
- 各記事の末尾「まとめ」セクションに**関連記事リンクを2〜3本**
- 本文中で他カテゴリの商品に言及する場合は**自然にリンク**
- 1記事あたり**内部リンク 3〜5本**（少なすぎ: 回遊されない、多すぎ: リンクジュース分散）
- 集客記事（Style F）→ 収益記事（Style A/E）への導線リンクは**必ず1本以上**

**アンカーテキストのルール:**
- KWを含むテキストにする（「こちら」「詳細はここ」は NG）
- 同じアンカーテキストを同一記事内で2回以上使わない
- 例: ○「ワイヤレスイヤホンのおすすめランキング」 ✕「おすすめ記事はこちら」

**優先リンク先:**
```
① 同一クラスターのピラー記事 — 最優先
② 同一クラスターの他のクラスター記事
③ 関連する別クラスターの記事
④ カテゴリ・タグページ（SEO効果は低いが回遊性向上）
```

### 8-3. カテゴリ / タグの使い分け

| 項目 | 用途 | 例 |
|---|---|---|
| **カテゴリ** | 記事の大分類（1記事1カテゴリ） | まとめ, レビュー, 解説 |
| **タグ** | 横断的な属性（1記事3〜6個） | 商品名, ブランド名, 価格帯, 用途, シーズン |

**タグの命名規則:**
- 商品カテゴリ名: 「ワイヤレスイヤホン」「ロボット掃除機」（表記揺れ防止）
- ブランド名: 「Sony」「Anker」「パナソニック」（英語/カタカナは公式表記に統一）
- 用途: 「テレワーク」「子育て」「時短」
- シーズン: 「花粉シーズン」「夏対策」「冬対策」

## 10. コンテンツ品質ガイドライン（E-E-A-T）

Google が重視する **E-E-A-T**（経験・専門性・権威性・信頼性）を意識する。

### 10-1. Experience（経験）— AIだけでは不可能な部分

- 「使ってみた」「試した」等の一人称体験を含める
- **使用期間・使用環境・家族構成**など具体的な情報を書く
- 良い点だけでなく**不満点も正直に**書く（信頼性の核心）
- **写真があれば最強**（オリジナル写真 > フリー素材 > 楽天API画像）

**AIへの指示ポイント:**
AIは体験を生成できないため、記事テンプレートの **TODO 箇所に「ここに実体験を挿入」マーカー** を設置し、人間が後から埋める運用とする。
```markdown
<!-- TODO: 実体験 — 実際の使用感（重さ、音、手触りなど五感情報）を記入 -->
<!-- TODO: 実体験 — 不満だった点を1〜2個正直に記入 -->
<!-- TODO: 実体験 — 使い始めて○日後の変化・気づきを記入 -->
```

### 10-2. Expertise（専門性）

- スペックの数値を正確に記載（メーカー公式サイトから引用 → `_snapshot.json` で検証）
- 専門用語には簡単な説明を添える（読者は非専門家が多い）
- 比較基準を**明確な軸**で設定する（「なんとなくおすすめ」は NG）
- ITエンジニアとしての知見を活かせる場面では積極的に出す（スマートホーム連携、API、Bluetooth規格等）

### 10-3. Authoritativeness（権威性）

- 「運営者情報」ページを充実させる（`content/page/about/`）
  - 名前（ハンドルネームOK）、経歴、資格、ブログの方針
- **1クラスターあたり5記事以上**で特定ジャンルの権威性を構築
- 記事内に参照元リンク（メーカー公式、公的機関のデータ等）を含める

### 10-4. Trustworthiness（信頼性）

- アフィリエイトリンクには `rel="nofollow noopener"` を付ける（✅ 実装済み）
- 価格は `_snapshot.json` の取得日を明記するか「※ 価格は執筆時点」と注記
- 免責事項・プライバシーポリシーを設置（✅ 実装済み）
- HTTPS 通信（✅ GitHub Pages は自動HTTPS）
- **記事末尾に更新日を表示**（鮮度シグナル）
- 景品表示法に基づく「PR」「広告」表記 → アフィリエイト記事には冒頭に明記

## 13. 画像SEO戦略

### 13-1. 画像種別と仕様

| 画像種別 | サイズ | 形式 | 目標容量 | 生成方法 |
|---|---|---|---|---|
| **カバー画像** | 960×400px | JPEG | 100KB以下 | `generate-covers.ps1` で自動生成（✅） |
| **OGP画像** | 1200×630px | JPEG/WebP | 200KB以下 | Canva or カバー画像を流用 |
| **商品画像（楽天）** | 400×400px | JPEG | — | 楽天CDN `?_ex=400x400` |
| **比較表画像** | 800×450px | WebP | 100KB以下 | Canva（必要に応じて） |
| **オリジナル写真** | 長辺1200px | WebP | 200KB以下 | スマホ撮影→WebP変換 |

### 13-2. alt属性の書き方

```
悪い例: alt="商品画像"
悪い例: alt="パナソニック NP-TSP1-W 食器洗い乾燥機 パナソニック Panasonic"（キーワード詰め込み）

良い例: alt="パナソニック NP-TSP1-W のキッチン設置イメージ"
良い例: alt="Sony LinkBuds の開封直後の外観"
良い例: alt="ワイヤレスイヤホン5機種の比較表"
```

ルール:
- **画像の内容を具体的に説明**する（装飾的な画像は `alt=""` でOK）
- KWの詰め込みはNG（Googleはスパム判定する）
- 商品名 + 何の画像か を簡潔に

### 13-3. 楽天API画像の高解像度化

`scripts/post.ps1` で楽天API画像を取得する際、`?_ex=400x400` を使用する。
※ 既に `shop-card.html` ショートコードでは `loading="lazy"` が設定済み。

## 14. 重複コンテンツ・カニバリゼーション対策

### 14-1. 重複コンテンツの防止

| リスク | 対策 |
|--------|------|
| 同じ商品を複数記事で詳しく紹介 | 詳細は1記事に集約し、他記事からは内部リンクで参照 |
| カテゴリページ・タグページとの重複 | `noindex` は不要（Hugoのページネーションで自動処理）。ただし薄いタグページは整理 |
| 年度更新で旧記事と新記事が並存 | 旧記事のslugに年度を入れないパターンにし、毎年リライトで更新。or 旧→新にリダイレクト |

### 14-2. タグの整理ルール

- 1記事にしか使われていないタグは**廃止候補**
- 表記揺れのあるタグは統一（「ワイヤレスイヤホン」と「Bluetoothイヤホン」を統一するか別にするか決める）
- 四半期ごとにタグ一覧を棚卸し

## 15. 分析・改善フレームワーク

### 15-1. KPI定義

| KPI | 短期目標（3ヶ月） | 中期目標（6ヶ月） | 計測ツール |
|-----|-------------------|-------------------|-----------|
| **月間PV** | 500 | 3,000 | GA4 |
| **検索表示回数** | 5,000/月 | 30,000/月 | Search Console |
| **平均CTR** | 3% | 5% | Search Console |
| **インデックス済み記事数** | 15 | 30 | Search Console |
| **アフィリエイト収益** | 月900円 | 月6,000円 | 楽天/Amazon管理画面 |
| **AdSense収益** | 月100円 | 月1,000円 | AdSense管理画面 |
| **平均滞在時間** | 2分 | 3分 | GA4 |
| **直帰率** | 70%以下 | 60%以下 | GA4 |

### 15-2. Google Search Console 分析ワークフロー

```
月次分析（毎月1日に実施）:

Step 1: 検索パフォーマンス → 過去28日間 → 「クエリ」タブ
  ├─ 表示回数TOP20のクエリを確認
  ├─ CTRが2%以下のクエリ → タイトル・ディスクリプション改善候補
  └─ 順位11〜20位のクエリ → リライト候補（TOP10入りの可能性大）

Step 2: 検索パフォーマンス → 「ページ」タブ
  ├─ 各記事のCTR・平均順位を確認
  └─ PVが少ない記事の原因分析（インデックスされていない？順位が低い？）

Step 3: インデックス → 「ページ」
  ├─ エラー/警告があれば即対応
  └─ 「検出 - インデックス未登録」が多い場合 → 内部リンク追加 or 手動リクエスト

改善アクション:
  CTR < 2%    → タイトルとdescription をリライト
  順位 11〜20 → 本文に500〜1000文字追加、見出し追加、内部リンク追加
  順位 21〜50 → 記事の大幅リライト or 切り口変更
  順位 50+    → 記事のKW変更を検討（カニバリ確認含む）
```

### 15-3. GA4 で見るべきレポート

| レポート | 見るべき指標 | アクション |
|----------|-------------|-----------|
| **ページとスクリーン** | PV数、滞在時間、直帰率 | 滞在時間が短い記事 → 冒頭を改善 |
| **トラフィック獲得** | チャネル別流入 | Organic Search の割合を追跡 |
| **イベント** | `click`（外部リンククリック） | アフィリエイトリンクのクリック率を追跡 |
| **ユーザー属性** | デバイス、地域 | モバイル比率を確認（80%以上ならモバイル最適化優先） |

**GA4 カスタムイベント（将来実装）:**
- `affiliate_click`: shop-card / shop-link のクリック計測
- `scroll_depth`: 25%/50%/75%/100% のスクロール到達を計測

### 15-4. リライト戦略

**リライト優先度の判断基準:**

| 優先度 | 条件 | リライト内容 |
|--------|------|-------------|
| 🔴 最優先 | 順位11〜20位 & 表示回数500+/月 | コンテンツ追加（+500〜1000文字）、見出し追加、内部リンク追加 |
| 🔴 最優先 | CTR < 2% & 表示回数1000+/月 | タイトル・description の改善のみ（本文は変えない） |
| 🟡 次点 | 順位21〜50位 | 大幅リライト: 構成見直し、KW再設定 |
| 🟡 次点 | 公開から3ヶ月経過 & 価格情報が古い | 価格・スペック情報の更新（鮮度シグナル） |
| 🟢 余裕があれば | 順位1〜10位（安定） | 微修正のみ: 内部リンク追加、最新情報の反映 |

**リライト時のルール:**
- リライト前にスクリーンショットを撮る（Before/After比較用）
- フロントマターの `date` を更新する（Hugo で更新日として表示）
- 1回のリライトで変更する箇所は**タイトル or 本文のどちらか**（両方同時に変えると効果測定不可）
- リライト後は Search Console でインデックス再リクエスト
