## 2. データ取得スクリプト

### 2-1. GSC レポート — `scripts/gsc-report.py`

**実行方法:**

```powershell
python scripts/gsc-report.py
```

**取得データ:**

| データ | 説明 | 出力ファイル |
|--------|------|-------------|
| クエリ別 | どんな検索キーワードで表示・クリックされたか | `gsc-data/queries_YYYYMMDD.csv` |
| ページ別 | ページごとの表示回数・クリック数・CTR・順位 | `gsc-data/pages_YYYYMMDD.csv` |
| 日別 | 日ごとの検索パフォーマンス推移 | `gsc-data/dates_YYYYMMDD.csv` |
| デバイス別 | PC / スマホ / タブレットの比率 | `gsc-data/devices_YYYYMMDD.csv` |
| サイトマップ | サイトマップの送信状況・インデックス数 | コンソール出力のみ |

**期間**: 過去28日間（API のデータは3日前まで）

**主要指標の意味:**

| 指標 | 意味 | 改善方法 |
|------|------|---------|
| 表示回数 (impressions) | Google 検索結果にページが表示された回数 | インデックス数を増やす、キーワード最適化 |
| クリック数 (clicks) | 検索結果からサイトに訪問した回数 | タイトル・ディスクリプション改善 |
| CTR (click-through rate) | 表示に対するクリック率 | タイトルの魅力度向上 |
| 掲載順位 (position) | Google 検索結果での平均順位 | コンテンツ品質向上、内部リンク強化 |

### 2-2. GA4 レポート — `scripts/ga4-report.py`

**実行方法:**

```powershell
python scripts/ga4-report.py
```

**取得データ:**

| データ | 説明 | 出力ファイル |
|--------|------|-------------|
| ページ別 PV | ページごとの閲覧数・ユーザー数・滞在時間・エンゲージメント率 | `ga4-data/pages_YYYYMMDD.csv` |
| 流入元 | Google 検索 / SNS / 直接 / 他サイト経由の比率 | `ga4-data/sources_YYYYMMDD.csv` |
| デバイス別 | PC / スマホ / タブレットのセッション数・PV | `ga4-data/devices_YYYYMMDD.csv` |
| 日別推移 | 日ごとのセッション・ユーザー・PV 推移 | `ga4-data/daily_YYYYMMDD.csv` |
| 外部リンククリック | アフィリエイトリンクのクリック数（URL別） | `ga4-data/outbound_clicks_YYYYMMDD.csv` |

**期間**: 過去28日間

**主要指標の意味:**

| 指標 | 意味 | 改善方法 |
|------|------|---------|
| screenPageViews (PV) | ページが表示された回数 | SEO改善、内部リンク |
| activeUsers | アクティブユーザー数 | 流入チャネルの拡大 |
| averageSessionDuration | 平均セッション時間 | コンテンツの質・量の向上 |
| engagementRate | エンゲージメント率（10秒以上滞在 or 2PV以上 or CVイベント） | 導線改善、目次・内部リンク |
| bounceRate | 直帰率（1ページのみで離脱） | 関連記事の提示、CTA改善 |

## 3. 分析観点とアクション

### 3-1. 定期分析（週次推奨）

両スクリプトを実行し、以下の観点でデータを確認する。

#### A. 検索流入の成長チェック（GSC）

```
確認項目:
- 表示回数は先週と比べて増えているか？
- 新しいクエリが出現しているか？
- 掲載順位が改善しているページはあるか？
```

**アクション基準:**

| 状態 | アクション |
|------|-----------|
| 表示あり・クリックなし（CTR 0%） | タイトル・メタディスクリプションを改善 |
| 順位 4〜10位 | コンテンツ追記・内部リンク強化で上位狙い |
| 順位 11〜20位 | リライト（見出し追加、情報更新、文字数増加） |
| 順位 20位以下 | キーワード再選定または記事統合を検討 |
| 新規クエリ出現 | そのクエリに最適化したセクションを追加 |

#### B. サイト内行動の把握（GA4）

```
確認項目:
- PV が多いページはどれか？（人気コンテンツの把握）
- 滞在時間が短いページはあるか？（コンテンツ改善の候補）
- 外部リンク（アフィリエイト）のクリック状況は？
- 流入元の比率（検索 vs 直接 vs SNS）
```

**アクション基準:**

| 状態 | アクション |
|------|-----------|
| PV 高い・滞在時間長い | 成功コンテンツ。類似記事を展開 |
| PV 高い・滞在時間短い | コンテンツ不足。追記・リライト |
| PV 低い・滞在時間長い | 流入が足りない。SEO 改善・内部リンク追加 |
| アフィリエイトクリック 0 | CTA の配置・文言を見直し |
| 直接アクセスが大半 | SEO がまだ弱い。検索流入の強化が最優先 |

#### C. GSC × GA4 クロス分析

| GSC データ | GA4 データ | 分析結果 | アクション |
|-----------|-----------|---------|-----------|
| 表示多い・クリック多い | PV 多い・滞在長い | 優良ページ | 関連記事を展開して収益化 |
| 表示多い・クリック少ない | — | タイトル/ディスクリプションが弱い | SERP でのクリック率を改善 |
| 表示少ない | PV 多い | 検索以外の流入（SNS/直接） | 検索向けにもキーワード最適化 |
| 順位高い（1〜3位） | アフィリエイトクリック多い | 収益の柱 | 情報鮮度を維持し続ける |
| 順位高い（1〜3位） | アフィリエイトクリック 0 | CTA が機能していない | ショップカード追加、文言改善 |

### 3-2. 記事公開後チェック（公開7日後）

新記事を公開した後、7日経過したら以下を確認する。

```
1. GSC でその記事 URL を検索
   - インデックス登録されているか？
   - 表示回数はあるか？
   - どんなクエリで表示されているか？

2. GA4 でそのページのパフォーマンスを確認
   - PV は発生しているか？
   - 滞在時間は十分か？（目標: 2分以上）
   - アフィリエイトリンクはクリックされているか？

3. 未インデックスの場合
   - Search Console の URL 検査で「インデックス登録をリクエスト」
   - または Google Ping を送信:
     https://www.google.com/ping?sitemap=https://mononikki.com/sitemap.xml
```

### 3-3. リライト判断基準

以下の条件に該当する記事はリライト候補とする。

| 優先度 | 条件 | リライト内容 |
|--------|------|-------------|
| **高** | GSC 順位 4〜10位 + 表示回数 10以上 | 最も投資対効果が高い。コンテンツ追記で上位狙い |
| **高** | GA4 滞在時間 30秒未満 + PV 5以上 | コンテンツが期待に応えていない。構成見直し |
| **中** | GSC 表示あり・CTR 2%未満 | タイトル・メタディスクリプションの改善 |
| **中** | GA4 アフィリエイトクリック 0 + PV 10以上 | CTA（ショップカード）の追加・配置変更 |
| **低** | GSC 順位 20位以下 | 記事統合 or キーワード変更を検討 |

## 4. インデックス管理

### 4-1. インデックス状況の確認

Search Console の「ページ」レポートで以下を監視する。

| ステータス | 意味 | 対策 |
|-----------|------|------|
| 登録済み | Google 検索に表示される | 正常。維持する |
| 検出 - インデックス未登録 | URL は発見済みだが未クロール | URL 検査でリクエスト or 待つ |
| クロール済み - インデックス未登録 | クロールされたが品質不足と判断 | コンテンツの追記・改善 |
| リダイレクトにより除外 | リダイレクトされている | 意図的なら OK |
| 重複（canonical 指定あり） | 正規 URL が別にある | 意図的なら OK |

### 4-2. インデックス促進

新記事公開後に以下を実行する。

1. **サイトマップ Ping 送信**
   ```
   https://www.google.com/ping?sitemap=https://mononikki.com/sitemap.xml
   ```
   ブラウザでアクセスするだけで OK。

2. **重要な記事は URL 検査から手動リクエスト**
   - Search Console → URL 検査 → URL 入力 → 「インデックス登録をリクエスト」
   - 1日あたり10〜20件の制限あり

## 5. CTR 改善のための目安

検索順位別の平均 CTR。自サイトの CTR がこれを下回る場合、タイトル・ディスクリプションの改善が必要。

| 掲載順位 | 平均 CTR 目安 |
|---------|-------------|
| 1位 | 約 30% |
| 2位 | 約 15% |
| 3位 | 約 10% |
| 4〜5位 | 約 5〜7% |
| 6〜7位 | 約 3〜4% |
| 8〜10位 | 約 1〜3% |

## 7. トラブルシューティング

### 認証エラーが出る場合

```
確認事項:
1. ~/.config/gsc-credentials.json が存在するか
2. サービスアカウントが Search Console / GA4 に追加されているか
3. API が Google Cloud Console で有効化されているか
```

### データが空の場合

```
GSC の場合:
- データ反映には3日のラグがある
- サイトが新しい場合、クロールに時間がかかる

GA4 の場合:
- 設定直後はデータなし（翌日から蓄積開始）
- 内部トラフィックフィルタで自分のアクセスが除外されている
- IP アドレスが変わった場合、フィルタの更新が必要
```

### モバイルからのアクセスも除外したい場合

1. スマホで https://api.ipify.org にアクセスして IP を確認
2. GA4 → 管理 → データストリーム → タグ設定 → 内部トラフィックの定義
3. 「条件を追加」でモバイル回線の IP を追加

> モバイル回線の IP は頻繁に変わるため、完全な除外は難しい。
> IP レンジ（CIDR）で指定するか、割り切って PC からのアクセスのみ除外する。

## 8. 執筆ワークフローへの統合

### 8-1. 統合の基本方針

分析データは **「参考情報」** であり **「制約」** ではない。
以下のバランスを常に意識する。

| やるべきこと | やってはいけないこと |
|-------------|-------------------|
| 伸びているテーマの派生記事を候補に含める | データがないテーマを候補から外す |
| リライト候補を発見したら著者に提案する | 新規記事よりリライトを優先しすぎる |
| アフィリエイトクリックの傾向を収益戦略に活かす | クリックされない記事を価値がないと判断する |
| CTR が低いページのタイトル改善を提案する | 少ないサンプル数で統計的に判断する |

### 8-2. サイトフェーズ別の活用度

データの活用度はサイトの成熟度に応じて自動調整する。

| フェーズ | 記事数 | 分析の活用度 | 新規テーマ開拓 | 主な判断軸 |
|---------|:------:|:-----------:|:------------:|-----------|
| 初期 | 〜50 | ★☆☆ 参考程度 | ★★★ 積極的 | トレンド・季節性・ペルソナ適合度 |
| 成長期 | 50〜150 | ★★☆ 判断材料の一つ | ★★☆ データも加味 | トレンド + GA4/GSC 実績 |
| 成熟期 | 150〜 | ★★★ データドリブン | ★☆☆ ギャップ埋め | GA4/GSC データが最優先 |

### 8-3. ワークフロー内での実行タイミング

```
daily-workflow.md の Phase 1 内:

  Step 0: サイト現況分析（自動実行）
  ├─ python scripts/gsc-report.py
  ├─ python scripts/ga4-report.py
  └─ サイト現況サマリーを出力
      ↓
  Step 1: 季節・時期の考慮
  Step 2: トレンド調査（ウェブ検索）
  Step 3: SEOキーワード選定
      ↓
  候補提示（サマリーの注目シグナルを候補に反映）
```

### 8-4. サイト現況サマリーの出力ルール

以下の条件に応じて出力内容を調整する。

**データが十分にある場合（GSC 表示 50+ / GA4 PV 100+）:**

全項目を出力し、注目シグナル（伸びているテーマ・リライト候補・CTA改善候補）を明示する。

**データが少ない/空の場合:**

「※ GA4/GSC データがまだ少ないため、トレンド調査を優先します」と1行で流し、
トレンド調査に進む。分析不足でワークフローを止めない。

**API エラーの場合:**

サイレントにスキップし、トレンド調査に進む。分析エラーでワークフローを止めない。

### 8-5. 注目シグナルの抽出ロジック

サイト現況サマリーの「注目シグナル」は以下のロジックで自動抽出する。

| シグナル | 条件 | アクション |
|---------|------|-----------|
| 🟢 伸びているテーマ | GSC で表示回数が先週比 +50%以上のページ | 関連する派生記事を候補に含める |
| 🟡 リライト候補 | GSC 順位 4〜20位 + 表示 10回以上 | 候補提示時にリライト提案を併記する |
| 🔴 CTA 改善が必要 | GA4 PV 10以上 + アフィリエイトクリック 0 | 該当記事のショップカード見直しを提案する |
| 🟣 検索流入の芽 | GSC に新規クエリが出現 | そのクエリに最適化した記事を候補に含める |

> 候補提示時に「📊 データからの提案」として最大2つまで併記する。
> ただし候補5つのうち最大1つまでにとどめ、残り4つはトレンド・季節性ベースで選ぶ。
