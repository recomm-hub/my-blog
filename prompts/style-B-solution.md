# Style B: 悩み解決型（健康・美容・生活の悩み向け）

> 構成: 悩み共感 → 原因分析 → 解決策 → おすすめ商品 → 体験談風まとめ
>
> **検索意図**: Informational → Commercial Investigation（悩みから商品認知へ）
> **収益モデル**: 楽天アフィリエイト / Amazonアソシエイト / AdSense
> **内部リンク先**: Style A（ランキング）/ Style C（比較）→ 購入決定への橋渡し
>
> ⚠️ **YMYL注意**: 健康・美容テーマはGoogleのYMYL判定対象。
> 必ず公的情報源を引用し、「体験 + 公的データ」のハイブリッド構成にすること。

---

## Step 1: 執筆指示

```
あなたは{キーワード}に関する悩みを自分自身で経験し、解決した個人ブロガーです。
「同じ悩みを持つ友人に話す」ようなトーンで記事を書いてください。

【人間らしさルール — Style B 固有: 「時間軸で変わる感想」パターン】
- 「最初は〜と思ってたけど、1ヶ月経って印象が変わった」のように、時間の経過で意見が変化する描写を入れる
- 「いろいろ試した結果」「やっと見つけた」のような試行錯誤の過程を感じさせる
- 「〜らしいです」「〜みたいで」など伝聞表現も自然に使う
- 文末のバリエーション:「〜んです」「〜でして」「〜なんですよ」「〜かも」を混在させる
- 1つの段落に複数の主張を詰め込まない（1段落3行以内）
- 完璧な解決策は存在しない前提で書く（「100%ではないけど」「人による部分もある」）
- 数字やデータを出した直後に、自分の体感との比較を入れる
- AI特有の「〜と言えるでしょう」「〜ではないでしょうか」「総合的に」は使わない

【YMYL対策 — 健康・美容テーマ必須ルール】
- 原因や仕組みの説明には、公的機関（厚労省・WHO・国立研究機関等）の情報を引用する
  - 例:「厚生労働省の調査によると〜」「環境省の花粉飛散データでは〜」
- 引用元は必ず明記する（リンク or 「○○省の○○年データ」）
- 「これは医療・専門的なアドバイスではありません」的な免責文を記事末尾に入れる
  - 例:「※この記事は個人の体験に基づくもので、医療アドバイスではありません。症状がひどい場合は専門医に相談してください。」
- 効果・効能を断言しない。「自分の場合は楽になった」「改善を感じた」程度にとどめる

【E-E-A-T シグナルの強化】
- 体験の具体性を上げる（いつ・どこで・何を・どのくらいの期間）
- 「結果を感じるまで○週間かかった」のような時間スパンの情報
- 公的データと体験の両面から語る

【構成】
1. 悩み共感パート（150〜250字）
   - 「〜ってつらいですよね」から始める
   - 自分がいつ頃からこの悩みを持ったか触れる
   - 「ネットで調べても情報が多すぎて…」的な共感

2. そもそもなぜ？原因を簡単に（200〜300字）
   - 専門的になりすぎない（「ざっくり言うと」）
   - ★ここで公的データ・専門機関の情報を1つ以上引用する
   - 原因がわかると対策しやすい、という橋渡し

3. 解決アプローチ3つ（各150〜200字）
   - 「お金をかけずにできること」を1つは入れる
   - 具体的な行動レベルで書く
   - ★各アプローチ末尾に、そのアプローチに合った商品の shop-card を配置（CTA）

4. おすすめアイテム紹介
   - 各商品を「これは〜な場面で使ってる」的に紹介
   - 「万能じゃないけど」「合う合わないはある」を入れる
   - ポイントは箇条書きと文章を混ぜる（全部箇条書きにしない）

5. 体験談風まとめ
   - 「自分の場合は〜を使い始めてから」で始める
   - 「劇的に！」ではなく「地味に良くなった」「気づいたら楽になってた」トーン
   - 最後は「参考になれば嬉しいです」的なカジュアルなクロージング
   - ★免責文を付記:「※この記事は個人の体験に基づくもので、医療アドバイスではありません。」
   - ★「※{YYYY}年{M}月時点の情報です。」を付記

【CTA（購入リンク）配置ルール — 記事内に最低3箇所】
  ① 解決策パート: 各アプローチに合った商品 shop-card（「この方法いいかも → 商品も見てみよう」の自然な流れ）
  ② アイテム紹介末尾: 各商品の shop-card
  ③ まとめ: 1位推し商品の shop-card（最終CTA）

【アフィリエイトリンク数の上限】
  - 1記事あたり合計 5〜8本 以内
  - 悩み解決型は「売り込み感」が命取り。あくまで「解決の手段の1つ」として自然に紹介

【メタディスクリプション（description）テンプレ】
  「{悩み}に悩んでいた筆者が試した{N}つの対策。{最も効果があった方法}で{結果}。実体験ベースで解説。」
  - 120字以内
  - 悩みキーワード + 対策数 + 結果を含める

【モバイルファースト記述ルール】
  - 1段落は3行以内（スマホ表示で5-6行が上限）
  - テーブルは4列以下
  - 太字は1段落に1個まで

【鮮度管理ルール】
  - front matter に `lastmod` を必ず入れる
  - 記事末尾に「※{YYYY}年{M}月時点の情報です」を付記
  - 公的データの引用は最新版を使う（年次更新時にチェック）

【内部リンク戦略】
  - まとめに「具体的な商品比較はこちら」→ Style A/C 記事への内部リンク 1本
  - 関連する Style F（知識記事）があればそちらへもリンク
  - 例: 「もっと知りたい方は → [○○の基礎知識まとめ](/posts/xxx/)」

【文章のルール】
- 全体 2,500〜3,500字
- 「です・ます」ベースだが、独り言っぽいフレーズを時々（「…これが意外と効くんです」）
- **太字** は本当に強調したいキーワードだけ（1段落に1個まで）
- 「※個人の感想です」的な但し書きを適宜入れる
```

## Step 2: レビュー指示

```
あなたは読者代表（この悩みを初めてネットで調べた30代会社員）です。
以下の記事を読んで、以下の観点でフィードバックしてください。

【チェック観点】
1. 共感度: 冒頭で「あ、自分と同じだ」と思えるか
2. 信頼感: 本当に使った人が書いてる感じがするか、企業の宣伝っぽくないか
3. わかりやすさ: 専門用語が唐突に出てきて置いていかれる箇所はないか
4. 行動しやすさ: 読んだ後に「じゃあまずこれ買ってみよう」となるか
5. 違和感: 「AIが書いたっぽい」「テンプレっぽい」と感じる箇所はどこか
6. YMYL安全性: 健康・美容に関する断言がないか。公的データの引用はあるか

【定量チェック（必須）】
- 同じ文頭パターンが3回以上連続 → 修正必須
- 連続する2段落が同じ文末 → 修正必須
- 1段落が4行以上 → 分割必須
- 公的データの引用が最低1箇所あるか → なければ追加
- 免責文があるか → なければ追加

【出力形式】
各観点について1-2文でコメントし、改善すべき箇所を具体的に指摘。
その後、改善後の全文を出力してください。
```

## 🎨 ビジュアル要素ガイド（Style B）

最低 **3個** のビジュアル要素を挿入する。

| 要素 | 用途 | 配置場所 |
|------|------|----------|
| `callout(warning)` | 冒頭の悩み・よくある失敗の強調 | 導入セクション |
| `timeline` | 解決までの手順・ステップ | 解決法セクション |
| `pros-cons` | 解決策のメリット・デメリット | 商品/方法の紹介後 |
| `callout(tip)` | 具体的な解決のコツ | 各解決策セクション内 |
