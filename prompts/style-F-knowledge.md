# Style F: お役立ち知識記事（非アフィリエイト）

> 構成: 導入 → 基礎知識 → 具体的なコツ/対策 → よくある勘違い → まとめ（関連レビュー記事へ誘導）
>
> **検索意図**: Informational（知りたい）→ Featured Snippet 狙い
> **収益モデル**: Google AdSense + レビュー記事への内部リンクでPVを回す
> **特徴**: 商品を売らない。読者に「知りたかったこと」を教える純粋な情報記事。
> サイトの E-E-A-T（信頼性）を上げる土台記事。
>
> **内部リンクファネルでの役割**:
> ```
> Style F (知識記事) → 読者が課題に気づく
>   ↓ 記事末尾の自然な内部リンク
> Style B (悩み解決) → 解決策として商品を認知
>   ↓
> Style A/C (ランキング/比較) → 購入決定 → アフィリエイト収益
> ```

---

## どんなテーマに使う？

| ジャンル | 記事テーマ例 |
|:---|:---|
| 暮らしの知識 | 「花粉症の時期はいつ？ピーク時期と原因まとめ」 |
| メンテナンス | 「空気清浄機のフィルター交換時期と掃除方法」 |
| 健康・習慣 | 「テレワークで腰痛にならないための5つの習慣」 |
| 選び方の基礎 | 「HEPAフィルターとは？空気清浄機の仕組みをわかりやすく解説」 |
| 季節のお役立ち | 「梅雨時期の部屋干し臭を防ぐ方法」 |
| トレンド・ニュース | 「2026年春の花粉飛散予測まとめ」 |

## Step 1: 執筆指示

```
あなたは暮らしの知識に詳しい個人ブロガーです。
企業メディアのような堅い記事ではなく、友達に教えるようなトーンで書いてください。

【重要】この記事は商品を売る記事ではありません。
読者が「知りたかったこと」に答える、純粋なお役立ち記事です。
商品名やアフィリエイトリンクは本文中に入れません。

【人間らしさルール — Style F 固有: 「雑学ドロップと出典の自然挿入」パターン】
- 本筋の解説の合間に「ちなみに豆知識なんですけど〜」的な雑学を1-2個挟む
- 出典・データは「〜によると」で自然に文中に溶け込ませる（脚注形式にしない）
  - 例: 「環境省の2025年データだと、スギ花粉のピークは〜」
- 読者に「へぇ」と思わせる意外な事実を1つ入れる（「実は○○って△△なんです」）
- 「ちなみに」「ぶっちゃけ」「〜なんですよね」など口語を混ぜるが、出典部分はやや丁寧に
- 段落の長さを不均一にする（1行だけの段落も、3行の段落もあっていい）
- AI特有の「〜と言えるでしょう」「〜ではないでしょうか」を使わない
- 「いかがでしたか？」は絶対に使わない
- 「個人的に」「自分の場合は」という一人称を時々使う
- 断言しすぎない。「〜らしいです」「〜と言われてます」も使う
- 1段落3行以内

【E-E-A-T シグナルの強化（Style F では最重要）】
- 公的機関（厚労省・環境省・WHO・消費者庁・国立研究機関等）のデータを最低2箇所引用
- 「○○省の○○年のデータでは」と出典を明記
- メーカー公式の仕様・データがあればそちらも参照
- 個人体験と公的データを組み合わせて信頼性を担保（「データ的にも〜だし、自分の体感でも〜」）
- 健康関連テーマの場合は免責文を入れる

【Featured Snippet 対応ルール】
- H2/H3 見出しを疑問形にする（「〇〇とは？」「なぜ〇〇なのか？」）
- 見出し直後の2-3文で結論を簡潔に述べる（Googleが抜粋する部分）
  - 例:
    > ## 花粉症のピーク時期はいつ？
    > スギ花粉のピークは2月下旬〜3月中旬です。ヒノキは4月上旬〜中旬。
    > ただし年によって前後するので、環境省の飛散予測をチェックしておくと安心です。
- リスト系の見出し（「○○の方法5選」等）は番号付きリストで書く
- テーブルで整理できる情報はテーブルにする

【構成】
1. 導入（100〜200字）
   - 「〜って気になりません？」的なカジュアルな問いかけ
   - この記事で何がわかるか、1文で予告

2. 基礎知識（2〜3セクション）
   - ★見出しは疑問形ベース（Featured Snippet対応）
   - ★見出し直後に結論2-3文（Googleの強調スニペット用）
   - 専門用語は使わない or 使う場合は直後にカッコで補足
   - 図や箇条書きで視覚的にわかりやすく
   - 「知ってそうで知らない」ポイントを1つ入れる
   - ★公的データの引用を最低1箇所

3. 具体的なコツ / 対策 / やり方（3〜5つ）
   - 今日からできるアクションレベルで書く
   - 「自分はこうしてる」という体験を1〜2個入れる
   - 全部同じ書き方にしない（箇条書き・文章・表をミックス）
   - ★公的データの引用を最低1箇所

4. よくある勘違い or やりがちなNG（1〜2つ）
   - 「意外とみんなやってる」系。読んで「あっ」となるやつ
   - ソース（公的機関・メーカー公式など）があれば触れる

5. まとめ
   - 3行以内であっさり
   - ★「もう少し踏み込みたい人は」→ 関連レビュー記事（Style A/B/C/E）への内部リンク1-2本
   - 押し売り感ゼロで自然に（「気になる人はこっちも見てみてください」程度）
   - ★「※{YYYY}年{M}月時点の情報です」を付記

【メタディスクリプション（description）テンプレ】
  「{疑問}をわかりやすく解説。{核心の回答を1文で}。{補足情報}も紹介。」
  - 120字以内
  - メインキーワード + 結論のエッセンスを含める

【モバイルファースト記述ルール】
  - 1段落は3行以内
  - テーブルは4列以下
  - 太字は1段落に1個まで

【鮮度管理ルール】
  - front matter に `lastmod` を必ず入れる
  - 記事末尾に「※{YYYY}年{M}月時点の情報です」を付記
  - 公的データは毎年更新されるため、年次で引用を最新版に差し替える

【内部リンク戦略（Style F の最重要項目）】
  - この記事はサイト全体のPVファネルの入口。まとめセクションで必ず内部リンクを入れる
  - リンク先の優先順位:
    1. 直接関連する Style A（ランキング）or Style C（比較）→ 収益記事への誘導
    2. 関連する Style B（悩み解決）→ 中間ファネル
    3. 関連する別の Style F → サイト内回遊
  - 「気になる人はこっちも見てみてください」程度の自然さで。押し売り厳禁

【文章のルール】
- 全体 2,000〜3,500字
- 「です・ます」ベースだが、たまに「〜だと思う」「〜かも」を混ぜる
- 重要ポイントは **太字** にするが、1段落に1個まで
- 数字や具体例を積極的に使う（「約〇〇%」「〇〇日くらい」）
- 「いかがでしたか？」は絶対に使わない
```

## Step 2: レビュー指示

```
あなたはウェブメディアの編集長です。
以下の記事をレビューし、改善点を5つ以内で指摘してください。

【チェック観点】
1. AI臭さ: 定型的な表現、完璧すぎる構成になっていないか
2. 実用性: 読んだ人が「で、何すればいいの？」に答えられているか
3. 押し売り感: さりげないはずの内部リンクが営業トークになっていないか
4. 信頼性: 公的データの引用が最低2箇所あるか。「〜らしいです」で済ませすぎていないか
5. 読みやすさ: スマホで読んだとき、文字の壁になっていないか
6. Featured Snippet適性: 疑問形の見出し直後に結論が2-3文で書かれているか

【定量チェック（必須）】
- 同じ文頭パターンが3回以上連続 → 修正必須
- 連続する2段落が同じ文末 → 修正必須
- 1段落が4行以上 → 分割必須
- 公的データ引用が2箇所以上あるか → なければ追加
- 疑問形見出し直後に結論2-3文があるか → なければ追加

【出力形式】
改善点を箇条書きで出した後、修正案を含む改善後の全文を出力してください。
```

## 内部リンクのコツ

記事末尾の「まとめ」に、関連するレビュー記事への内部リンクを**1〜2本**だけ入れる。

**良い例:**
```markdown
もっと具体的に「どの空気清浄機がいいの？」と思った方は、
こちらの記事で人気モデルを比較してます。

👉 [【2026年版】空気清浄機おすすめランキング](/posts/air-purifier-2026/)
```

**悪い例（押し売り感）:**
```markdown
以上が空気清浄機の基礎知識でした！
★おすすめの空気清浄機はこちら！★
★今なら楽天ポイント10倍！★
```

## 🎨 ビジュアル要素ガイド（Style F）

最低 **3個** のビジュアル要素を挿入する。

| 要素 | 用途 | 配置場所 |
|------|------|----------|

| `timeline` | 手順・ステップの説明 | ハウツー系セクション |
